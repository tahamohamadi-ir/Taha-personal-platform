# **1\. تعریف محصول**

این وب‌سایت صرفاً یک Personal Website، رزومه آنلاین، Portfolio یا Blog نیست.

محصول باید به **مرکز اصلی هویت دیجیتال، حرفه‌ای، پژوهشی و دانشی طه محمدی** تبدیل شود و چهار حوزه را در یک معماری منسجم ترکیب کند:

1. **Academic & Research Identity**  
2. **Professional & Engineering Identity**  
3. **Knowledge, Writing & Teaching**  
4. **Creative & Personal Identity**

تمام این حوزه‌ها باید:

* Content Model مشترک  
* Taxonomy مشترک  
* Relationship Layer مشترک  
* Search مشترک  
* Design System مشترک

داشته باشند.

اما Presentation آنها باید متناسب با مخاطب تغییر کند.

اصل:

> **One Identity, Multiple Audience Paths**

# **10\. Evidence Policy**

یکی از اصول اصلی سایت:

> **Evidence over Claims**

برای تمام ادعاهای مهم باید Evidence وجود داشته باشد.

Evidence می‌تواند شامل:

* Quantitative impact  
* Published work  
* Repository  
* Demo  
* Architecture  
* Screenshots  
* Dataset  
* DOI  
* Citation  
* Award  
* Reference  
* Organizational context  
* Verified outcome

باشد.

## **Quantification Rule**

اگر Metric معتبر موجود باشد، نمایش داده شود.

مثلاً:

* Reduced processing time by X%  
* Used by X users  
* Processed X records/day  
* Improved response time from A to B  
* Citation count  
* Number of deployments  
* Course participants

اما:

**هیچ عدد تخمینی یا غیرقابل اثبات صرفاً برای جذاب‌تر شدن صفحه تولید نشود.**

اگر عدد قابل انتشار وجود نداشته باشد از Evidence کیفی استفاده شود.

# **25\. Outcome & Impact Rule**

برای Experience و Project همیشه یک Outcome section وجود داشته باشد.

### **Quantitative**

اگر اطلاعات واقعی موجود است.

### **Qualitative**

اگر Metric قابل انتشار وجود ندارد.

مثلاً:

* Enabled feature X  
* Replaced manual workflow  
* Improved maintainability  
* Reduced operational complexity  
* Supported enterprise integration

نباید بدون Evidence از عباراتی مانند:

“massively improved”

یا

“highly scalable”

استفاده شود.
